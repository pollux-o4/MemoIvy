# DATA-001 · 메모 파일 형식과 로드

- SQLite가 현재 메모의 저장 원본이다. 이전 버전의 가져오기 입력은 Note 객체의 JSON 배열이다. 필드·타입 원본은 `Note`, 허용 색상은 `COLORS`다.
- 의미: id=메모의 안정적 UUID, text=일반 텍스트, color=팔레트 키, modified=Unix 초 단위 수정 시각.
- canvas: 위치·방향 연결 UUID·완료 상태·포함한 프로젝트(parent)·바로가기 고정(pinned)·프로젝트 정체성(project). 필드 생략 시 기존 메모로 로드하고 배치를 정한다. parent·pinned·project는 기본값이면 쓰지 않는다. project는 기본 false이며 포함 관계의 부모·기존 고정 기록은 로드 때 true로 승격한다(PROJECT-003). 메모 UUID가 카드 식별자다.
- 검증
  - JSON·필수 필드·타입·UUID, 중복 ID, 허용 색상을 검사한다.
  - 캔버스 좌표는 -LIMIT 이상 LIMIT(20,000) 이하의 유한한 값(원점 위·왼쪽도 허용), 연결은 실제 존재하는 다른 메모 UUID로 검증한다. 중복·자기 연결은 거부한다.
  - parent는 실제 존재하는 다른 메모여야 하며 순환과 최상위 아래 세 단계를 넘는 깊이를 거부한다(PROJECT-001). 메모 삭제 시 자식은 한 단계 위로 올린다.
  - 방문 기록은 엔진 설정으로 저장한다(NAV-001).
  - 이전 파일을 발견하지 못하면 빈 목록으로 시작한다. 이전 파일의 읽기 오류는 원본을 보존하고 표시한다.
- 호환성
  - 이전 JSON 형식에는 버전 필드가 없으며 Serde가 추가 필드를 허용한다.
  - 향후 필수 필드·허용 값 변경 시 기존 파일 변환 또는 명시적 오류·원본 보존을 제공한다.
- 이전 파일은 자동 탐색하거나 설정에서 선택한다. 변경 이력이 없는 빈 저장소로 가져오며 JSON 원본과 검증한 백업을 보존한다.
- 완료 기준: Electron E2E의 ‘이전 메모 자동·수동 가져오기’에서 본문 및 첨부 재열기와 원본·백업 비교를 확인한다. 엔진은 반복 잠금 실패 후 재시도를 검사한다.  한글·이모지 roundtrip, 손상·중복 ID·잘못된 색상 거부와 원본 보존.
