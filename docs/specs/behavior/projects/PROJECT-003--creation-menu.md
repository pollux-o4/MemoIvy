# PROJECT-003 · New 생성 선택과 빈 프로젝트

- 범위·근거: 기본 목록과 캔버스 오른쪽 위의 공통 생성 메뉴에서 메모·프로젝트를 구분해 만들고, 비어 있는 프로젝트도 유지한다. `+ New`에 별도 펼침 화살표를 붙이지 않는다.
- 생성: 메뉴의 메모는 현재 단계에 만들고 메모 편집기를, 프로젝트는 현재 단계에 빈 프로젝트를 만들고 이름·설명을 적는 프로젝트 편집기를 연다. Ctrl+N과 빈 화면의 첫 메모 만들기는 즉시 메모를 생성한다. 선택을 묶는 Alt+G도 같은 프로젝트 생성 트랜잭션을 사용한다.
- 정체성: `canvas.project`가 프로젝트 판별의 단일 원본이다. 마지막 메모 이동·삭제 뒤에도 프로젝트로 남는다. 목록·캔버스 카드·이동 대상·경로·바로가기가 이를 공유한다. 빈 프로젝트에는 메모 0개와 캔버스 진입을 표시하고, 프로젝트별 목록의 섹션·머리글 펼침은 PROJECT-002를 따른다.
- 호환·저장: 필드 없는 기존 파일을 읽는다. 포함 관계의 부모와 기존 고정 기록은 저장 경계에서 프로젝트로 승격한다. 로드만으로 파일을 덮어쓰지 않고, 다음 정상 저장에 반영한다. 최초 생성 저장에 종류를 포함하며 저장 실패 시 미완성 객체를 게시하지 않는다. 사용자 원문·수정 시각은 승격만으로 바꾸지 않는다.
- 깊이·동시성: 깊이 규칙은 저장 계층이 판단하고 메뉴는 허용 여부를 반영한다. 새 프로젝트는 메모를 담을 여유가 있는 깊이에만 생성한다. 쓰기 진행 중 생성 선택은 비활성이다. 순환·깊이 초과·없는 부모는 기존 불변식으로 거부한다.
- 모션: 버튼의 오른쪽 위 기준점에서 약 280ms 동안 표면 너비·높이·모서리·배경색이 감속 보간되고 선택 항목이 나타난다. New의 +는 닫기 방향으로 회전한다. 표면의 New 또는 Esc로 접을 때 현재 모션에서 반전한다. 선택과 바깥 클릭은 네이티브 팝오버 닫기를 사용한다. 시스템 애니메이션이 꺼지면 즉시 반영한다.
- 렌더링·경계: 모핑 표면은 팝오버를 소유하지 않고 닫힘 완료만 알린다. 조립 코드는 표면 내부 상태에 접근하지 않는다. 애니메이션은 GSK 노드의 클립·색·변환과 프레임별 redraw로 처리하며, 진행 중 재배치 없이 종료 시 콜백을 해제한다. 60Hz(16.67ms)를 목표로 하고 합성 프레임 간격 p95 33.4ms 이상의 지속 누락을 회귀 검사로 잡는다. 실제 GPU 표시 프레임 보장과 구분한다.
- 접근성: 펼침 상태는 네이티브 MenuButton, 메뉴 포커스·외부 클릭은 Popover가 담당한다. 첫 메모 항목에 포커스를 두고 Tab·방향키·Enter/Space·Esc로 조작한다. 닫으면 생성 버튼으로 복귀한다. 메모·프로젝트·캔버스 SVG에는 접근성 이름을 제공한다.
- 검증: `mise run test project_003`이 원자 생성·실패 복구·이전 파일·고정 기록·깊이·빈 프로젝트 이동 대상·마지막 메모 이동을 확인한다. `mise run test:canvas`, `mise run test:storage`, `mise run test:arch`로 연결된 규칙을 확인한다. OPS-003 환경에서 `python3 -m tools.behavior.lifecycle.project_003_ui_smoke`를 밝은/어두운 테마로 실행해 실제 모션 프레임·Enter/포인터·Esc/바깥 클릭·Ctrl+N·재실행·원문 보존을 확인한다. 실제 Wayland·IME·스크린리더 검증과 구분한다.
