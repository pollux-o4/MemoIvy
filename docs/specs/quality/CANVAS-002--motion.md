# CANVAS-002 · 캔버스 모션과 피드백

- 범위: 확대·이동·전체 보기, 카드 재배치, 방향 신호·도착, 선택·호버 깊이, 메뉴 등장. 위치·연결 저장 계약은 CANVAS-001. 선택 이유: ADR-0009.
- 카메라: 화면 중심과 로그 배율을 넘치지 않는 스프링으로 옮긴다. 전환 중 입력은 속도를 유지한 채 새 목표로 이어진다. 끌기 시작은 진행 중 이동을 멈춘다. Ctrl+스크롤·핀치는 포인터 아래 지점을 고정하고 즉시 반영한다. 터치패드 입력은 직접 따르고 손을 뗀 뒤 추가 관성은 약 0.3초·100 화면 픽셀 이내로 제한한다. 약한 놓기는 추가 관성이 없고 새 스크롤·끌기·핀치·보드 경계·모션 줄이기는 관성을 즉시 중단한다. 확대 제스처 뒤에는 이동 관성을 붙이지 않는다. 내용이 화면에서 완전히 사라지도록 이동할 수 없다.
- 카드: 정렬·되돌리기·방향키 이동은 살짝 넘치는 스프링으로 미끄러진다. 저장되는 위치는 목표 좌표이며 움직이는 중 값을 저장하지 않는다. 끄는 카드는 포인터를 바로 따르고 그림자로 떠오른다. 새 카드는 확대·페이드로 등장한다.
- 신호: 직계 연결을 따라 꼬리가 있는 점이 이동하고 도착 카드 둘레에 퍼지는 테두리를 표시한 뒤 사라진다. 대상 완료 상태를 바꾸지 않는다. 반복 전송은 최근 신호로 대체한다. 새 연결은 시작점부터 그려진다.
- 모션 줄이기: GTK 애니메이션 비활성화 시 카메라·카드를 즉시 반영하고 신호는 정적 도착 표시만 제공한다. 실행 중 설정 변경도 진행 중 전환에 적용한다. CSS 전환도 같은 설정을 따른다.
- 자원·입력: 활성 전환이 끝나면 프레임 콜백을 중단하고 유휴 CPU를 쓰지 않는다. 확대·이동 프레임마다 카드를 재생성하거나 저장 요청을 만들지 않는다. 배경 점 수는 배율과 무관하게 제한한다. 화면 밖 카드·저배율 표현 기준은 PERF-002. 변경 후 사라진 패널 컨트롤의 포커스는 연결 추가로 복구한다.
- 프레임 타이밍: GTK 프레임 클록에 맞춰 실제 경과 시간을 적용한다. 첫 프레임을 60Hz로 가정하거나 적분 시간을 올림하지 않는다. 60/120/144Hz·프레임 간격 흔들림에서도 이동 거리와 정지 조건을 유지하며 작은 이동의 서브픽셀 좌표를 보존한다.
- 완료 기준: 스프링의 단조성·재목표 속도 유지·프레임률 독립, 카메라의 앵커 고정·중앙 맞춤·내용 유지, 기존 위젯 유지, 모션 줄이기를 CANVAS-002 테스트로 확인한다. 밝은/어두운 테마의 호버·선택·확대·도착은 실제 GTK 화면에서 검토한다.
- 한계: 시각 스타일의 선호를 사용자 연구 결과로 해석하지 않는다. macOS와 동일한 플랫폼 합성 효과(반투명 흐림)를 보장하지 않는다. 합성기·GPU가 있는 실제 세션의 프레임률은 별도 확인 대상이다.

- 설계 근거: [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)의 짧고 중단 가능한 모션, [ProMotion 타이밍 가이드](https://developer.apple.com/documentation/quartzcore/optimizing-iphone-and-ipad-apps-to-support-promotion-displays)의 주사율 독립·프레임 동기를 적용했다. 감속 수치는 이 앱의 제품 결정이며 Apple의 지정값이 아니다.
