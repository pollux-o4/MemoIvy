# ADR-0011 · 내용 주소 기반 첨부 파일

- 맥락: 스크린샷을 메모에 붙인다. 스크린샷 폴더는 자주 일괄 삭제되므로 원본 경로를 가리키면 이미지가 깨진다. 같은 이미지를 여러 메모에 쓰거나, 지웠다가 다시 쓰는 일도 흔하다.
- 대안
  - 외부 경로 링크: 저장 공간이 들지 않지만 원본이 지워지면 깨진다.
  - notes.json에 base64로 넣기: 파일 하나로 끝나지만 300ms마다 다시 쓰는 snapshot이 커져 PERF-001 입력 반응을 해친다.
  - 메모별 폴더: 메모 삭제와 함께 지우기 쉽지만 같은 이미지가 중복되고 메모 간 복사가 깨진다.
- 결정: 붙여 넣거나 끌어 놓은 이미지 바이트를 복사해 `assets/<sha256>.<형식>`으로 저장하고, 본문은 `asset:<sha256>`으로 참조한다(DATA-003). 사용처 색인은 notes.json과 분리한 파생 데이터다.
- 삭제: 본문에서 참조가 사라져도 파일은 남는다. 파일 영구 삭제는 파일 화면의 사용 안 함 항목에서만 하고, 30일 자동 정리는 사용자가 켤 때만 동작한다(FILE-001).
- 결과
  - 스크린샷 폴더를 비워도 메모 이미지는 유지된다. 같은 이미지는 한 번만 저장된다.
  - 백업 대상이 notes.json과 assets 폴더 둘이 된다(OPS-002).
  - 참조 판정은 원문 문자열 검색이라, 인용문·코드 안의 `asset:` 표기도 사용 중으로 본다. 잘못 지우는 것보다 덜 지우는 쪽을 택했다.
- 재검토: 영상·PDF 같은 다른 형식을 받거나, 동기화 기능이 생기면 형식 판별과 색인 위치를 다시 판단한다.
