# MIG-001 · MemoIvy 데스크톱 전환과 화면 검수 개선

## 목적
- 세 운영체제에서 같은 메모 기능을 제공한다
  - Windows와 macOS와 Linux에서 사용합니다
  - [Electron과 Rust 엔진을 단일 설치 패키지에 동봉한다]
- 화면 상태를 즉시 재현해 검수한다
  - 저장 실패와 긴 본문도 앱 전체 실행 없이 확인합니다
  - [React·TypeScript·Vite와 Storybook으로 실제 화면을 개발한다]

## 포함 범위
- 기능별 모듈과 얇은 계층으로 전환한다
  - 함께 바꾸는 기능을 가까이 두고 외부 경계만 분리합니다
  - [frontend는 app·features·shared, desktop은 창과 OS, engine은 domain·application·storage·transport를 맡는다]
- 기존 도메인 규칙을 화면과 분리해 재사용한다
  - 저장 기술이 바뀌어도 메모의 동작과 데이터 의미를 보존합니다
  - [persistence의 domain·Notebook 규칙을 재사용하고 JSON 큐·직접 파일 저장은 SQLite adapter로 교체한다]
- 실제 화면과 같은 이야기 화면을 만든다
  - 빈 상태와 긴 본문과 중첩 프로젝트와 저장 실패를 바로 봅니다
  - [같은 React 컴포넌트에 실제 adapter 또는 mock adapter를 주입한다]
  - [UI-001·ADR-0012의 공통 disclosure, 다크 모드·좁은 창·키보드 접근성을 이관한다]
- 메모 한 개의 저장과 복원을 먼저 연결한다
  - 열기부터 재실행 복원까지 작은 기능으로 구조를 검증합니다
  - [목록과 편집을 Electron preload·main 및 Rust transport에 연결한다]
- 목록과 편집기와 캔버스를 순차 이관한다
  - 기능을 옮길 때 해당 책임과 중복을 정리합니다
  - [목록·프로젝트 이후 편집기·첨부, 마지막으로 캔버스·history를 이관한다]
- 저장을 검증된 내장 데이터베이스로 옮긴다
  - 트랜잭션과 복구는 검증된 저장 기술에 맡기고 메모 규칙은 유지합니다
  - [SQLite를 Rust 저장 adapter에 도입하고 schema version·트랜잭션·foreign_keys를 관리한다]
  - [기존 JSON은 읽기 전용으로 백업 후 원자적으로 가져오고 재실행 중복·실패 rollback을 검증한다]
  - [메모·연결·프로젝트 변경은 단일 트랜잭션으로 커밋하며 첨부 파일 정리는 커밋 후 수행한다]

## 제외 범위
- 원격 서비스 분리와 일괄 추상화는 제외한다
  - 제품은 하나로 배포하고 실제 필요한 경계만 둡니다
  - [실제 교체 요구 없는 Repository·Service·UseCase 계층은 추가하지 않는다]

## 제약
- 원본 데이터와 저장 정책은 엔진이 소유한다
  - 화면 초안과 저장 완료를 구분하고 실패해도 입력을 보존합니다
  - [단일 writer와 디바운스를 유지하고 SQLite commit 성공 뒤 생성·삭제 결과를 게시한다]
- 여러 창이 하나의 엔진을 공유한다
  - 같은 메모의 충돌과 오래된 응답을 감지합니다
  - [request ID·protocol version·base revision·saved revision과 snapshot 구독 순서를 정의한다]
- 자동저장은 실패했을 때만 사용자를 방해한다
  - 정상 편집과 닫기에는 저장 버튼이나 확인창을 요구하지 않습니다
  - [백그라운드 자동저장과 종료 flush를 유지하며 durable 확인은 앱 내부에서 처리한다]
  - [일반 창 닫기는 조용히 처리하고 앱 종료 때 미저장 데이터가 있으면 저장 완료 후 종료한다]
  - [저장 실패·시간 초과 때만 오류와 재시도를 제공하며 초안을 보존하고 조용히 버리지 않는다]
- 합의한 방향 안에서 계약 변경을 진행한다
  - 이 전환의 공개 계약 변경은 재확인 없이 구현하고 변경 근거를 남깁니다
  - [요청·응답·이벤트 계약과 호출부·테스트를 같은 변경으로 갱신하고 Rust·TypeScript 불일치를 차단한다]
  - [사용자가 승인한 이번 전환 범위에 적용하며 파괴적 데이터 삭제나 외부 배포로 확대하지 않는다]
- 기존 데이터와 외부 입력을 보호한다
  - 기존 앱과 새 앱의 동시 쓰기를 막고 원본 백업을 유지합니다
  - [합성 데이터 사용, OS별 경로·Snap 가져오기·파일 잠금·복구 검증을 포함한다]
  - [nodeIntegration 비활성화, contextIsolation·sandbox·CSP, IPC sender·payload와 HTML·경로·링크를 검증한다]
- 엔진 통신과 장애 복구를 명시한다
  - 연결이 끊기면 초안을 보존하고 작업 결과를 다시 확인합니다
  - [Electron main이 Rust 자식 프로세스를 관리하며 프레임 단위 JSON은 stdio, 로그는 stderr를 사용한다]
  - [요청 시간 초과·잘못된 메시지·종료를 처리하고 비멱등 작업을 무조건 재전송하지 않는다]
- 역할을 이름 검색으로 찾을 수 있게 한다
  - 폴더와 주요 타입 이름만으로 책임과 경계를 알 수 있게 합니다
  - [기능은 library·editor·canvas로, 저장은 sqlite_store로, 통신은 engine_transport로 명명한다]
  - [범용 utils·manager 이름을 피하고 책임에 맞게 코드를 배치한다]
- 기존 화면의 외형을 유지하며 이관한다
  - 배치와 크기와 색과 조작 위치를 원본에 맞춥니다
  - [UI-REF-001의 GTK 원본과 같은 fixture·테마·실제 치수로 Storybook에서 비교한다]

## 완료 기준
- 화면 상태와 키보드 조작을 단독 검수한다
  - 앱과 저장 엔진 없이 같은 화면을 확인합니다
  - [Storybook 빌드·타입 검사와 펼침·포커스·저장 실패 상호작용 검증을 통과한다]
- 현재 가능한 환경부터 동작을 확인한다
  - 현재는 Linux에서 실행해 확인하고 다른 운영체제는 환경 확보 후 확인합니다
  - [Mac이 없는 상태에서 macOS 직접 검수를 완료 조건으로 걸지 않는다]
  - [운영체제별 자동 검사 체계와 서명 작업을 이번 변경의 필수 과업으로 추가하지 않는다]
- 저장 실패와 창 충돌에서도 초안을 보존한다
  - 저장 실패를 성공으로 표시하거나 무조건 재전송하지 않습니다
  - [엔진 중단·응답 역전·종료 flush·생성 삭제 실패·백업 복원을 검증한다]
- 편집기와 캔버스의 기존 조작을 보존한다
  - 한글 입력과 선택과 되돌리기가 실제 사용에서 유지됩니다
  - [IME·커서·Markdown·붙여넣기·첨부와 팬·줌·다중 선택·연결·history를 검증한다]
- 영향 범위 검증 후 기존 화면을 제거한다
  - 동등 기능과 데이터 복구 확인 후 기존 구현을 정리합니다
  - [mise run test:storage·test:arch 등 변경 영역만 검증하고 전체 테스트는 요청 시 실행한다]
  - [GTK 제거 후 ADR·C4·운영 명령을 갱신하며 사용자 변경과 미요청 커밋·배포를 보존한다]
- 원본 화면을 이후 검수의 기준 자산으로 보관한다
  - 다른 담당자도 원래 화면을 확인하고 차이를 검수할 수 있게 합니다
  - [docs/assets/gtk-reference의 원본 PNG 18개·데이터·manifest와 Storybook 비교 화면을 유지한다]
  - [일반 빌드·테스트에서 기준 이미지를 갱신하지 않고 사용자 요청 시만 재캡처한다]
